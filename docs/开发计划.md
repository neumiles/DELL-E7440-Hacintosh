## 迭代 1：进入 Big Sur / 修复花屏（当前）

**现状**：可进入 Recovery，但画面花屏（重影/马赛克）；Big Sur 尚未进入。

**根因判断**：与 EFI2 全面对比后，核显 framebuffer 参数完全一致，差异在 **WhateverGreen 版本（1.4.9 vs 1.4.1）**。花屏「重影/马赛克」是显存（stolenmem/fbmem）异常表现，怀疑 WhateverGreen 新版本对 Haswell HD4400 的回归。BIOS 近期未改动，排除 BIOS 因素。

**已实施**：降级 WhateverGreen 1.4.9 → 1.4.1（分支 `fix/huaping-weg`）

- [ ] 1.5 完成 Big Sur 启动进入桌面

### 验收标准

**现状**：hibernatemode 25 下睡眠触发 ShutdownCause 5 关机；纯 S3 正常。详见 [E7440-休眠问题复盘报告](E7440-休眠问题复盘报告.html)。

### 任务清单（沿用复盘报告优先级）

- [ ] 3.3 成功解析 `shutdown_stall` 二进制报告，定位关机发起者

### 备选方案（如休眠无法解决）

| 方案 | 说明 | 可行性 |
|------|------|--------|
| 放弃休眠，纯 S3 | `hibernatemode 0 + standby 0` | 已知可行 |
| 升级到更新 macOS | 新系统 RTC 处理可能有变化 | 不确定 |
| 更换 SMBIOS | 不同机型电源管理策略不同 | 低 |

## 开发流程规范

1. **分支策略**：每项任务开 `feat/xxx` 或 `fix/xxx` 分支，完成验证后合并 `main`
2. **提交规范**：`类型: 简述`（`fix` / `feat` / `docs` / `test` / `chore`）
3. **同步机制**：改动先在仓库内迭代，验证通过后 `rsync` 同步到 TF 卡 EFI 分区
4. **回滚能力**：任何改动失败，可 `git checkout` 回退到上一稳定版本
